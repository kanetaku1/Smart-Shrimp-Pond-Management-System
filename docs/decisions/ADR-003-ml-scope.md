# ADR-003: 予測層はインターフェース定義に留め、Phase 1はルールベースで実装する

**Status:** `DECIDED`
**日付:** 2026-09-09

## Context
学習に利用可能な実データが存在するか不明であり、実際の養殖池へのアクセスもない。
この状態で学習済みMLモデルの精度を提案の前提に置くことはできない。

## Options
- A: MLをスコープから削除する
- B: 予測・検知層のインターフェースのみ設計し、Phase 1実装は統計・ルールベースとする
- C: 合成データで学習したモデルを成果物として主張する

## Decision
**B を採用。**

- 予測・検知層は **差し替え可能なインターフェース** として設計する（入出力スキーマを確定）
- Phase 1 実装は統計・ルールベース：レンジチェック / 移動平均±3σ / 変化率 / stuck値検出 / 欠損検出
- 学習モデルは Phase 2 とし、インターフェースを変えずに差し替える

## Reason
- データがない段階でモデル精度を主張することは、提案として誠実でない
- 設計書 §15.5 の Phase 分けと既に整合している
- §36 Rule 8「できることと仮説を明確に分ける」の直接的な実践
- インターフェースを先に固定することで、データが得られ次第Phase 2に移行できる（§36 Rule 3）

## Consequences
- 設計書 §26 の Week 5 を「MLモデル構築」から
  「Anomaly Detection Service（IF確定＋ルールベース実装）」へ書き換える
- 空いた工数は Agent（Week 7）と統合・評価（Week 8）へ再配分、およびバッファとする
- 提案書 §2.4 の比較表では、ML Predictionを「実装済み」ではなく
  「インターフェース設計済み・Phase 2」として記載する

## Open Questions
- Phase 2 移行の判断基準（必要データ量・期間）
