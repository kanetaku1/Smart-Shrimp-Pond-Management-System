## 2. データ要件

- **収集データ項目（IoT）**：DO（溶存酸素）、pH、水温、濁度、TDS、水位
- **収集データ項目（日次入力）**：給餌量、死亡回収数、エサ残り具合、業務日報等
- **収集データ項目（週次入力）**：サンプリング尾数、合計重量
- **データ取得方法**：IoTは自動取得、日次・週次データはTechnical Managerによる入力
- **データ粒度・頻度**：IoTは3〜5分間隔、日次データは1日1回、週次データは週1回程度
- **データの見え方の違い**：
  - Technical Manager：自ファームの全池について、IoT・日次・週次の詳細データをそのまま確認可能
  - Farms Manager：生センサー値・詳細な現場入力値は見えず、KPI・アラートをもとに算出された分析結果（スコア・推奨・予測）、集約トレンド、分析根拠のみ確認可能
- **データ形式・命名規則**：分析しやすい形式で設計（ファーム・池単位で識別可能な命名規則とする）
- **AI予測アドバイス用データ**：IoTセンサーの時系列データ（DO・pH・水温・濁度・TDS・水位の推移）を学習データとして使用

### 11.1 日次報告書 入力項目（一次案）

> 実際の運用に合わせて現場へのヒアリングを行い、確定させる前提の一次案です。

| 項目             | 内容（例）                               | 必須             |
| ---------------- | ---------------------------------------- | ---------------- |

## 3. 外部インターフェース要件

- **IoTセンサー**：現場設置の防水型スマートプローブ（DO・pH・水温・濁度・TDS・水位計測）
- **アクチュエーター**：ポンプ・エアレーション等の自動制御対象機器（PID制御・Safety Layer経由で制御）
- **通信ネットワーク**：LoRaWAN／4G／5G
- **データ基盤**：センサー → Edge → GCP（Google Cloud Platform）という流れでデータを収集・蓄積することを想定（システム設計書に準拠）
- 気象API等、外部データソースとの連携

## 4. 非機能要件

| 分類                                        | 要件例                                                                                                                                                                                                                       |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 性能                                        | 3〜5分間隔の連続データ受信・処理に耐えるレスポンス性能                                                                                                                                                                       |
| 可用性                                      | 通信断絶（LoRaWAN／4G／5G障害）時のデータ欠損対応                                                                                                                                                                            |
| セキュリティ                                | 役職別アクセス権限（RBAC）、Farms Managerには詳細数値を見せない権限制御、通信の暗号化                                                                                                                                        |
| 安全性（自動制御）                          | 自動制御が誤作動した場合にも安全側に倒れるSafety Layerを備えること。Technical ManagerによるHuman Overrideをいつでも優先できること                                                                                            |
| ユーザビリティ（Farms Manager側表示ルール） | ステータスは色分け（正常／注意／警告）で統一表示、画面上部に結論を一文で表示、推奨アクションと根拠（主要因）を併記、予測値と実績値を明確に区別、最新データ時点を必ず表示、重大なアクションは「要確認」状態とし自動実行しない |
| 拡張性                                      | エステート数・池数の増加に対応できる設計                                                                                                                                                                                     |
| 動作環境                                    | Farms Manager：PC（マルチディスプレイ等）／Technical Manager：PC・タブレット等                                                                                                                                               |
